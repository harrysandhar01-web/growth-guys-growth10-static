How to Reconcile a GROWTH10 Cart Total

A cart total is easiest to understand when each line keeps its own job: merchandise subtotal first, GROWTH10 discount second, and shipping, tax, sales, or payment-method adjustments separately.

Answer first: compare the displayed GROWTH10 reduction with the eligible merchandise subtotal. Do not describe the entire difference between a product price and a later total as the code discount unless the cart labels every component that way.

1. Start with the eligible merchandise subtotal

Write down the merchandise subtotal before the code. If the eligible subtotal is CAD 100 and GROWTH10 displays a CAD 10 reduction, the code arithmetic is 100 × 0.10 = 10. The after-code merchandise amount is CAD 90.

This is a calculation example, not a new verification event. A current claim belongs to the current GROWTH10 record and its dated evidence.

2. Keep a merchant sale separate

A sale changes the displayed product price before or alongside the coupon calculation. If an item is shown at CAD 80 after a merchant sale and GROWTH10 removes CAD 8, the code reduction is CAD 8. The combined difference from an earlier CAD 100 reference price is not all a GROWTH10 discount.

3. Read the remaining lines independently

  • Shipping: a delivery charge, not automatically part of the coupon base.
  • Tax: a separate calculation that may depend on location and taxable lines.
  • Payment-method adjustment: a separate displayed condition that should not be merged into the code result.
  • Displayed total: the sum shown for that cart state; it is not necessarily the same as the merchandise amount.

4. Reconcile before comparing two records

When comparing dated GROWTH10 records, match product context, quantity, currency, subtotal, code reduction, total, and any separately displayed adjustment. A lower total can come from a different item, sale price, shipping state, tax calculation, or payment presentation rather than a larger code discount.

Also keep cart states separate. If a visible payment-method change causes the merchant to refresh or recalculate the cart, the exact site code must be re-entered and the final displayed result treated as the relevant state.

5. Report what the record actually shows

A useful record names the code, date, cart context, eligible subtotal, displayed reduction, and stated boundary. It does not turn arithmetic into a promise about every product or future session. The current record answers the status question; the archive preserves older observations; this guide explains how to read the numbers.
